# Job Market Intelligence & Skills Analytics — DEPI R5 Final Project

Multi-source job-posting pipeline **and interactive intelligence dashboard** that helps
Egyptian and Arab engineers see where tech opportunities are (Arab, international, remote),
which skills they require, what pay is advertised and what to learn next.
Full planning and requirements: `Project Documentation33_final.pdf`.

The dashboard works on **588,545 unique postings** from 8 sources (159 countries, 1,475
skills). Every figure shows its population and provenance: skills written in the posting vs
added by the team, advertised salaries vs market benchmarks, the 2023 Kaggle archive vs the
2024–26 collection. Findings describe the collected sample, not the whole labour market.

## Quick start

Requires **Python 3.12+** (pinned numpy 2.5 / pandas 3.1) and **Node.js 20+**.

```bash
python -m venv .venv && .venv\Scripts\activate        # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
# put the raw files in data/raw/ (see "Data"), then:
python src/pipeline.py                                 # raw -> data/processed/ + reports/   (~2-3 min)
python src/build_analytics.py                          # -> data/analytics/jmi.duckdb        (~3 s)
cd frontend && npm ci && npm run build && cd ..        # -> frontend/dist
uvicorn api.main:app --port 8000                       # open http://localhost:8000
```

No raw data? `python scripts/make_demo_data.py` builds a clearly-labelled **synthetic**
store; run the API with `JMI_DB=data/analytics/demo.duckdb`. Development mode, hosting and
troubleshooting: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Dashboard modules

| | |
|---|---|
| **Overview** | KPIs with denominators, roles, skills (written vs team-added), the role × skill *lattice*, countries, markets, seniority, pay, collections, sources |
| **Job explorer** | server-side search, every filter, sort, pagination, posting detail with skill provenance and the original link |
| **Skills** | demand, technical vs soft, segment lattices, co-occurrence heatmap + network, skill profiles |
| **Salaries** | advertised pay by role/country/seniority/skill/employer with quartiles; benchmarks in a separate view |
| **Geography** | choropleth, concentration, country table, Arab League markets, role mix by country |
| **Employers** | directory and profiles (job boards flagged; sample counts, not company size) |
| **Time & cohorts** | monthly trends within 2023 only; the two collections as side-by-side snapshots |
| **Compare markets** | two segments, normalized, with sample-size / cohort / source warnings |
| **Career planner** | target role + your skills → alignment, what to learn next, adjacent roles, matching postings |
| **Guided insights / Insight builder** | query-grounded sentences; build and export your own aggregates |
| **Data & methodology** | pipeline counts, completeness, provenance, the Sudan correction, definitions, limits |

Filters live in the URL (shareable links), every chart has a table view and PNG/CSV export,
light and dark themes, keyboard accessible, responsive down to phones.

## Outputs

`data/processed/jobs_clean.csv` — one row per unique posting (UTF-8 with BOM, opens correctly in Excel / Power BI):

| Column | Meaning |
|---|---|
| `job_id` | stable unique id |
| `title`, `company`, `description` | cleaned text (encoding fixed, Arabic normalized, emails/phones removed) |
| `role_category`, `seniority` | rule-based from the title (baseline for the ML classifier) |
| `country`, `city`, `location`, `region` | standardized location; `region` = Arab / Non-Arab / Worldwide |
| `market_type` | **Remote** if remote, else **Arab** if in an Arab League country, else **International** |
| `work_mode`, `job_type`, `language` | standardized categories |
| `skills`, `skills_count`, `skills_observed_count` | canonical skills joined by `; `; how many were in the posting data as collected |
| `skills_enriched` | True = some skills were added by the team, not written in the posting |
| `salary_min/max/currency/period`, `salary_usd_annual` | parsed salary, annualized, approx. USD |
| `salary_is_estimate` | True = market benchmark attached by the team, not the posting's pay |
| `posted_date`, `posted_year` | Kaggle rows are 2023, API rows Oct 2026 |
| `source_dataset`, `source_platform`, `sources`, `duplicate_count` | provenance; `sources` lists every platform a merged duplicate came from |

`data/processed/job_skills.csv` — long table `(job_id, skill, is_observed)`; `is_observed` = the skill was in the
posting data as collected (False = added by the team). Use it for strict skill-demand analysis.

`data/processed/skills_dim.csv` — one row per skill: `category`, `category_source` (kaggle / curated / none),
`is_technical`.

## Cleaning rules (summary)

1. Each source is loaded by its own function and mapped to one staging layout.
2. Text: `ftfy` encoding repair, Arabic normalization (diacritics, tatweel, أ/إ/آ→ا, ى→ي, Arabic digits), whitespace.
3. Personal data: emails → `[email]`, phone numbers → `[phone]`.
4. Country: aliases unified; the merged file's `job_country` ("Sudan" = search location for 21k US jobs) is ignored; missing countries are read from the location text.
5. Job type (~120 spellings → 6 values), seniority, role category, language.
6. Skills parsed from 3 list formats, synonyms merged (`k8s` → Kubernetes, `.NET`, tag spellings), one display
   spelling each; each (posting, skill) is marked observed or team-added from the original source lists.
7. Salaries parsed from free text (currency, range, `k`, period) → annual USD with fixed approximate rates.
8. Rows without title and clearly non-tech roles (sales, HR, finance) are dropped.
9. Deduplication: exact duplicates, then same title + company + location + country (placeholder companies such as "Confidential" also compare date + description); the most complete copy is kept.

See `reports/data_quality_report.md` for counts at every stage and the known limitations.
