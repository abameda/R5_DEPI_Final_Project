# Job Market Intelligence & Skills Analytics — DEPI R5 Final Project

Multi-source job-posting pipeline that helps Egyptian and Arab engineers see where tech
opportunities are (Arab, international, remote) and which skills they require.
Full planning and requirements: `Project Documentation33_final.pdf`.

## Repository layout

```
data/raw/            raw source files (not in git, see "Data" below)
data/processed/      pipeline outputs (not in git)
src/clean_utils.py   reusable cleaning rules (text, PII, country, market, skills, salary)
src/loaders.py       one loader per source -> shared staging columns
src/pipeline.py      runs everything: load -> clean -> deduplicate -> save + report
scripts/00_peek_raw.py   quick column profile of every raw file
notebooks/01_EDA_and_cleaning.ipynb   EDA of the raw data (problems) and the clean data (findings)
reports/data_quality_report.md        generated by the pipeline (FR-11)
tests/test_clean_utils.py             unit tests for the cleaning rules (NFR-24)
```

## Outputs

`data/processed/jobs_clean.csv` — one row per unique posting (UTF-8 with BOM, opens correctly in Excel / Power BI):

| Column | Meaning |
|---|---|
| `job_id` | stable unique id |
| `title`, `company`, `description` | cleaned text (encoding fixed, Arabic normalized, emails/phones removed) |
| `role_category`, `seniority` | rule-based from the title (baseline for the ML classifier) |
| `country`, `city`, `location`, `region` | standardized location; `region` = Arab / Non-Arab / Worldwide |
| `market_type` | **Remote** if remote, else **Arab** if in an Arab League country, else **International** |
| `work_mode`, `job_type`, `language` | standardized categories |
| `skills`, `skills_count` | canonical skills joined by `; ` |
| `skills_enriched` | True = some skills were added by the team, not written in the posting |
| `salary_min/max/currency/period`, `salary_usd_annual` | parsed salary, annualized, approx. USD |
| `salary_is_estimate` | True = market benchmark attached by the team, not the posting's pay |
| `posted_date`, `posted_year` | Kaggle rows are 2023, API rows Oct 2026 |
| `source_dataset`, `source_platform`, `sources`, `duplicate_count` | provenance; `sources` lists every platform a merged duplicate came from |

`data/processed/job_skills.csv` — long table `(job_id, skill)` for skill-frequency analysis and the dashboard.

## Cleaning rules (summary)

1. Each source is loaded by its own function and mapped to one staging layout.
2. Text: `ftfy` encoding repair, Arabic normalization (diacritics, tatweel, أ/إ/آ→ا, ى→ي, Arabic digits), whitespace.
3. Personal data: emails → `[email]`, phone numbers → `[phone]`.
4. Country: aliases unified; the merged file's `job_country` ("Sudan" = search location for 21k US jobs) is ignored; missing countries are read from the location text.
5. Job type (~120 spellings → 6 values), seniority, role category, language.
6. Skills parsed from 3 list formats, synonyms merged (`k8s` → Kubernetes), one display spelling each.
7. Salaries parsed from free text (currency, range, `k`, period) → annual USD with fixed approximate rates.
8. Rows without title and clearly non-tech roles (sales, HR, finance) are dropped.
9. Deduplication: exact duplicates, then same title + company + location + country (placeholder companies such as "Confidential" also compare date + description); the most complete copy is kept.

See `reports/data_quality_report.md` for counts at every stage and the known limitations.
